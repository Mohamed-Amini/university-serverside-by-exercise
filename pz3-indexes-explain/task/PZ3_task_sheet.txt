Практическое задание №3.
Оптимизация запросов и индексы
Курс: Серверное программирование
Лекция: Л3 — Оптимизация
A . Общая постановка
Цель: провести нагрузочное тестирование БД и оптимизировать типовой запрос с
помощью индексов.
Контекст: Используется схема и данные из ПЗ1–2.
Требования
1. Предзаполнить таблицы до ≥500 000 записей суммарно.
2. Сформулировать типовой запрос: ≥3 таблицы, ≥3 условия WHERE , разные типы данных.
3. Зафиксировать план и время выполнения до оптимизации.
4. Добавить индексы, перестроить их, повторить замеры.
5. Оформить таблицу: индексы → время → стоимость запроса.
Критерии приёмки
☐ ≥500 K записей
☐ EXPLAIN ANALYZE до и после
☐ Таблица сравнения производительности
☐ Выводы об эффективности индексов
Отчёт: SQL запроса, планы EXPLAIN , таблица замеров, выводы.
B . Референсная реализация ( Java + PostgreSQL )
Стек: PostgreSQL, EXPLAIN (ANALYZE, BUFFERS), CREATE INDEX, REINDEX.
Подготовка
 ПЗ2 выполнено: связи и ≥10 K записей на месте.
 Типовой запрос приложения из ПЗ2 можно взять за основу и усложнить.

Пошаговая реализация
Шаг 1. Массовая загрузка до 500 K + записей
Цель: получить объём данных, при котором разница между Seq Scan и Index Scan заметна.
Используем: generate _ series , COPY , отключение индексов на время загрузки
(опционально)
Догрузите данные до ≥500 000 записей суммарно. Для ускорения можно временно
удалить неключевые индексы и создать их после загрузки.
INSERT INTO book (title, author_id, year)
SELECT md5(random()::text), (random()*1000+1)::int, 1950 + (random()*75)::int
FROM generate_series(1, 500000);
Шаг 2. Формулировка типового тяжёлого запроса
Цель: получить запрос, который соединяет ≥3 таблицы и фильтрует по ≥3 условиям разных
типов.
Используем: JOIN , WHERE (строки, числа, даты)
Составьте запрос, имитирующий реальную нагрузку: несколько JOIN , фильтрация по
строке, числу и дате, сортировка или LIMIT .
SELECT a.name, b.title, b.year
FROM book b
JOIN author a ON a.id = b.author_id
JOIN category c ON c.id = b.category_id
WHERE a.name LIKE 'A%'
AND b.year BETWEEN 2000 AND 2020
AND c.code = 'FICTION'
ORDER BY b.year DESC
LIMIT 100;
Шаг 3. Замер «до оптимизации»
Цель: зафиксировать базовый план и время выполнения без целевых индексов.
Используем: EXPLAIN (ANALYZE, BUFFERS, FORMAT TEXT)
Выполните EXPLAIN ANALYZE . Сохраните план, обратите внимание на Seq Scan , cost , actual
time и количество прочитанных буферов ( shared hit / read ).
EXPLAIN (ANALYZE, BUFFERS, FORMAT TEXT)
SELECT ... -- ваш запрос

Шаг 4. Создание и перестройка индексов
Цель: добавить индексы на столбцы из WHERE и JOIN , затем перестроить их.
Используем: CREATE INDEX , REINDEX
Создайте индексы по одному, каждый раз повторяя EXPLAIN ANALYZE . После массовой
загрузки выполните REINDEX для актуальной статистики.
CREATE INDEX idx _ book _ year ON book ( year );
CREATE INDEX idx _ author _ name ON author ( name );
REINDEX INDEX idx _ book _ year ;
Шаг 5. Замер «после оптимизации» и таблица результатов
Цель: сравнить производительность и сформулировать выводы.
Используем: EXPLAIN ANALYZE , таблица в отчёте
Повторите EXPLAIN ANALYZE с полным набором индексов. Заполните таблицу: какие
индексы созданы → время выполнения → cost корневого узла → тип сканирования ( Seq
Scan / Index Scan / Bitmap Scan ).
