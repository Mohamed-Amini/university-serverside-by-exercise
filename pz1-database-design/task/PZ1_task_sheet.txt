Курс: Серверное программирование
Лекция: Л1 — Введение в базы данных
A. Общая постановка
Цель: спроектировать архитектуру БД предметной области и реализовать базовые
таблицы с данными.
Контекст: Выберите предметную область — она будет использоваться во всех
последующих работах курса.
Требования
1. Определить предметную область и оформить архитектуру БД (UML или ER, минимум 5
таблиц).
2. Создать схему данных: таблицы, типы столбцов, первичные ключи.
3. Заполнить каждую таблицу не менее чем 10 записями.
4. Составить запрос CROSS JOIN по всем созданным таблицам.
Критерии приёмки
☐ Диаграмма модели данных (≥5 таблиц)
☐ DDL-скрипт создания таблиц
☐ Дамп или скрипт заполнения данными
☐ SQL CROSS JOIN с результатом выполнения
Отчёт: диаграмма, SQL-скрипты, скриншоты выполнения запросов.
B. Референсная реализация (Java + PostgreSQL)
Стек: PostgreSQL 16+, pgAdmin или DBeaver, SQL.

Подготовка
 Установить PostgreSQL с официального сайта postgresql.org или postgrespro.ru
 Создать роль и базу данных для учебного проекта.
 Подключиться через pgAdmin, DBeaver или psql.
Пошаговая реализация
Шаг 1. Выбор предметной области и проектирование модели
Цель: получить согласованную логическую модель данных, которую можно реализовать в
PostgreSQL.
Используем: бумага / draw.io / DBeaver ER-диаграмма
Определите предметную область (библиотека, интернет-магазин, расписание занятий и
т.д.). Выделите сущности, их атрибуты и первичные ключи. Минимум 5 таблиц.
Зафиксируйте модель в виде ER- или UML-диаграммы — она понадобится в следующих
работах.
Шаг 2. Создание пользователя и базы данных
Цель: изолировать учебный проект в отдельной БД с выделенными правами доступа.
Используем: psql или pgAdmin
Создайте роль и базу. Подключитесь к новой БД от имени созданного пользователя.
CREATE USER sp_user WITH PASSWORD 'secret';
CREATE DATABASE sp_course OWNER sp_user;
\\\\c sp_course sp_user
Шаг 3. Реализация DDL — создание таблиц
Цель: перенести логическую модель в физическую схему PostgreSQL.
Используем: SQL, SERIAL/BIGSERIAL, PRIMARY KEY, NOT NULL
Для каждой сущности напишите CREATE TABLE. Укажите типы столбцов (INTEGER, TEXT,
VARCHAR, DATE, BOOLEAN и т.д.) и первичные ключи. При необходимости используйте
SERIAL для автоинкремента.
CREATE TABLE author (
id SERIAL PRIMARY KEY,
name TEXT NOT NULL
);
CREATE TABLE book (

id SERIAL PRIMARY KEY,
title TEXT NOT NULL,
year INTEGER
);
Шаг 4. Заполнение таблиц тестовыми данными
Цель: получить достаточный набор данных для проверки запросов (минимум 10 строк в
каждой таблице).
Используем: INSERT, множественный INSERT, \\\\copy (опционально)
Добавьте данные через INSERT или загрузите CSV через \\\\copy. Данные должны быть
осмысленными в рамках предметной области.
INSERT INTO author (name) VALUES
('Толстой'),
('Достоевский'),
('Пушкин');
INSERT INTO book (title, year) VALUES
('Война и мир', 1869),
('Преступление и наказание', 1866);
Шаг 5. CROSS JOIN по всем таблицам
Цель: показать декартово произведение всех таблиц и понять его cardinality.
Используем: SELECT, CROSS JOIN (или запятая в FROM)
Составьте запрос, соединяющий все созданные таблицы через CROSS JOIN. Обратите
внимание на количество строк в результате: оно равно произведению числа строк каждой
таблицы.
SELECT *
FROM author
CROSS JOIN book;
