Шаг 3. REST -контроллер: GET и DELETE
Цель: реализовать чтение списка и удаление ресурса по id через Repository .
Используем: @ RestController , @ GetMapping , @ DeleteMapping , AuthorRepository

Создайте контроллер с внедрением AuthorRepository (@ RequiredArgsConstructor ). GET
возвращает List < Author > в JSON . DELETE вызывает deleteById и возвращает 204.
@RestController
@RequestMapping(\\"/api/authors\\")
@RequiredArgsConstructor
public class AuthorController {
private final AuthorRepository repository;
@GetMapping
public List<Author> list() { return repository.findAll(); }
@DeleteMapping(\\"/{id}\\")
public ResponseEntity<Void> delete(@PathVariable Long id) {
repository.deleteById(id);
return ResponseEntity.noContent().build();
}
}
Шаг 4. REST -контроллер: POST (создание)
Цель: принимать JSON в теле запроса и сохранять сущность через Repository .
Используем: @ PostMapping , @ RequestBody
Добавьте POST -метод с @ RequestBody Author . Сохраните через repository . save () и верните
созданный объект с 200 OK .
@PostMapping
public ResponseEntity<Author> create(@RequestBody Author author) {
return ResponseEntity.ok(repository.save(author));
}

Часть 2. Транзакции (Л8)
Шаг 7. Сервисный слой и @ Transactional
Цель: вынести бизнес-логику из контроллера в сервис и обеспечить атомарность
операций, затрагивающих несколько сущностей.
Используем: @ Service , @ Transactional , propagation REQUIRED
Создайте AuthorService с методом, выполняющим несколько изменений в БД (например,
создать автора и несколько связанных книг). Пометьте метод @Transactional — при
RuntimeException все изменения откатятся.
@Service
@RequiredArgsConstructor
public class AuthorService {
private final AuthorRepository authorRepo;
private final BookRepository bookRepo;
@Transactional
public Author createAuthorWithBooks(Author author, List<Book> books) {
Author saved = authorRepo.save(author);
books.forEach(b -> { b.setAuthor(saved); bookRepo.save(b); });
return saved;
}
}
Шаг 8. Демонстрация rollback
Цель: показать, что при ошибке внутри транзакции данные не сохраняются частично.
Используем: @ Transactional , намеренное исключение, READ COMMITTED

Вызовите сервисный метод, который после save () бросает RuntimeException . Проверьте в
БД: ни автор, ни книги не должны сохраниться. Затем выполните тот же сценарий без
ошибки — данные должны появиться.
@Transactional
public void transferDemo(Long fromId, Long toId, BigDecimal amount) {
Account from = accountRepo.findById(fromId).orElseThrow();
Account to = accountRepo.findById(toId).orElseThrow();
from.debit(amount);
to.credit(amount);
// throw new RuntimeException(\\"test rollback\\");
accountRepo.save(from);
accountRepo.save(to);
}
Шаг 9. Настройка readOnly и обработка ошибок
Цель: оптимизировать read -операции и корректно возвращать HTTP -статусы из REST .
Используем: @Transactional(readOnly = true), ResponseEntity, @ExceptionHandler
Для GET -методов сервиса используйте @ Transactional ( readOnly = true ). В контроллере
обрабатывайте EntityNotFoundException → 404 Not Found . Задокументируйте в отчёте:
какой уровень изоляции использует PostgreSQL по умолчанию.
@Transactional(readOnly = true)
public List<AuthorBookDto> getAuthorBooks() { ... }
@ExceptionHandler(EntityNotFoundException.class)
public ResponseEntity<Void> notFound() {
return ResponseEntity.notFound().build();
}
